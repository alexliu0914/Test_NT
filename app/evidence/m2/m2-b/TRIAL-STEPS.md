# M2-b 試用步驟（協作游標與儲存狀態）

在 M2-s 試用的環境（Windows、Docker Desktop、原本的 `notes_dev` 資料庫、四個帳號、兩個共享空間）上進行。四個彼此獨立的瀏覽器視窗各登入一個帳號：A（管理者）、B、C、D。M2-b 沒有資料庫遷移。

## 準備：切換到 M2-b

```powershell
git fetch origin
git checkout -b m2b origin/m2b   # 已有 m2b 分支時改用：git checkout m2b; git pull
cd app
npm ci
npm run dev                      # 網頁
npm run collab                   # 協作伺服器（另開一個終端機）
```

先在 A、B、C 都是成員的共享空間建立一個頁面「游標測試」，D 開另一個頁面。

## 步驟與預期結果

請在每一步的「結果」欄填「通過」或描述看到的情況。

| # | 操作 | 預期 | 結果 |
| --- | --- | --- | --- |
| 1 | A、B、C 開「游標測試」，各自在文件中點一下或打幾個字 | 編輯區上方列出另外兩人的名字（帳號名稱）與顏色，三人顏色不同；文件中看到對方的游標，移動或打字時游標旁顯示名字，約 1 秒內跟上 | |
| 2 | D 停在另一個頁面 | D 的畫面看不到 A、B、C 的游標；A、B、C 的名單中沒有 D | |
| 3 | A 在同一個瀏覽器再開一個分頁到「游標測試」，再關掉它 | 開著時 B、C 看到兩個 A 的游標（同名同色）；關掉後只剩一個 | |
| 4 | B、C 在同一段落同時連續打字 | 兩人打的字都在、畫面一致；停手後狀態回到「已儲存」 | |
| 5 | B 在某一段打字時，C 刪除那一段（選取整段後刪除） | 不當機、不出現錯誤；兩人畫面最後一致；其他段落不受影響 | |
| 6 | B 拔網路線或關閉 Wi-Fi，繼續打字 | 幾秒內（最多約 8 秒）狀態變成「離線，內容保存在此裝置」，不會顯示「已儲存」或「儲存失敗」；A、C 的名單上 B 最多 30 秒內消失 | |
| 7 | B 在離線狀態直接關閉瀏覽器，恢復網路後重新打開「游標測試」 | 剛才離線打的字還在；短暫顯示「儲存中」後變成「已儲存」；A、C 也看到這些字 | |
| 8 | 在 `app` 資料夾的終端機暫停資料庫：`docker compose -f docker-compose.test.yml pause postgres`，A 繼續打字約 10 秒 | 狀態變成「儲存失敗」（不是「已儲存」）；重新整理前不要關閉頁面 | |
| 9 | 恢復資料庫：`docker compose -f docker-compose.test.yml unpause postgres` | 約 10 秒內狀態回到「已儲存」；剛才打的字只出現一次，B、C 也看到 | |
| 10 | A 打字後立刻在側邊欄點另一個頁面（或先停止協作伺服器再點） | 修改已同步時直接切換；尚未同步時先短暫等待，仍未同步就詢問「這一頁還有尚未同步的修改」；選「留在此頁」不切換。切換後側邊欄該頁旁標示「未同步」，回到該頁同步後標示消失 | |
| 11 | B 用第二個瀏覽器（或無痕視窗）再登入一次並開「游標測試」；在第二個瀏覽器的「設定 → 登入裝置」撤銷第一個 | 被撤銷的那個 2 秒內顯示「登入已失效」，A、C 看不到它的游標；另一個的游標仍在 | |
| 13 | A、B 都在「游標測試」最後一個空白行點一下（兩人游標在同一行）。B 從其他文件複製一段含標題與清單的內容貼上；A 看到 B 的內容出現後，也貼上另一段 | A 的游標所在空白行被 B 的內容換掉時，A 那裡出現一個新的空白行；A 貼上後兩人的標題、清單各自完整，沒有合併成同一段；畫面與重新整理後一致 | |
| 14 | B 在某一段打字；A 在同一段開頭按 Ctrl+Alt+1（改成標題），B 同時繼續打字（可請 B 拔網路線打幾個字再接回） | 該段變成標題，B 打的字全部都在、沒有重複；A 先關閉瀏覽器再讓 B 恢復網路，結果相同 | |
| 15 | 接續上一步：B 在標題裡再打幾個字後，A 按 Ctrl+Z，再按 Ctrl+Shift+Z | Ctrl+Z 後回到一般段落、B 的字都在；Ctrl+Shift+Z 後又是標題、B 的字都在；A 復原後再打幾個字，接著按 Ctrl+Shift+Z 不會有任何變化 | |
| 16 | 四個瀏覽器都重新整理 | 名單、游標、內容與重新整理前一致；所有頁面都是「已儲存」 | |

步驟 8 用「暫停」而不是「停止」資料庫：暫停時連線還在但無法寫入，可以看到「儲存失敗」；恢復後不需要重新啟動網頁或協作伺服器。
