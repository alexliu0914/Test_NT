# M2-b 試用步驟（協作游標與儲存狀態）

在 M2-s 試用的環境（Windows、Docker Desktop、原本的 `notes_dev` 資料庫、四個帳號、兩個共享空間）上進行。四個彼此獨立的瀏覽器視窗各登入一個帳號：A（管理者）、B、C、D。M2-b 沒有資料庫遷移。

## 準備：切換到 M2-b

```powershell
git fetch origin
git checkout -b m2b origin/m2b   # 已有 m2b 分支時改用：git checkout m2b; git pull
cd app
npm ci
npm run build                    # 正式模式建置（約 1～2 分鐘）
npm start                        # 網頁（正式模式），一樣是 http://localhost:3000
npm run collab                   # 協作伺服器（另開一個終端機）
```

請用正式模式（`npm run build` 後 `npm start`），不要用 `npm run dev`：開發模式下 Ctrl+Z／Ctrl+Shift+Z 完全沒有作用（FAILURES.md F-M2-12，只影響開發模式），自動化測試與正式部署都是正式模式。程式更新（`git pull`）後要重新執行 `npm run build`。

先在 A、B、C 都是成員的共享空間建立一個頁面「游標測試」，D 開另一個頁面。

## 如何模擬離線（步驟 6、7、13）

網頁與協作伺服器都在本機時，拔網路線或關閉 Wi-Fi 不會中斷瀏覽器與本機伺服器的連線，請改用瀏覽器的開發人員工具模擬離線（只影響那一個分頁，其他帳號的視窗不受影響）：

1. 在 B 的「游標測試」分頁按 F12（或 Ctrl+Shift+I）開啟開發人員工具。
2. 切到「網路」（Network）分頁。
3. 把上方的節流選單從「不節流」（No throttling）改成「離線」（Offline）。開發人員工具要保持開著，關掉就會恢復連線。
4. 恢復連線：把選單改回「不節流」。

自動化測試 COL-10 用的是同一個機制（瀏覽器的離線模擬，會觸發離線事件）。如果瀏覽器沒有這個選項，可以改為在協作伺服器的終端機按 Ctrl+C 停止它（這時所有帳號都會離線，步驟 6 的「A、C 名單上 B 消失」就無法觀察），步驟 7 改為停止協作伺服器後關閉 B 的瀏覽器，再重新執行 `npm run collab`，然後打開 B。

步驟 14 的復原（Ctrl+Z）只包含 A 在這次開啟頁面後自己做的修改，不會復原別人的修改；重新整理或關閉瀏覽器後復原紀錄會清空，這時按 Ctrl+Z 沒有反應是正常的。

步驟 8 用「暫停」而不是「停止」資料庫：暫停時連線還在但無法寫入，可以看到「儲存失敗」；恢復後不需要重新啟動網頁或協作伺服器。
