# M2-s 試用步驟（四個帳號、兩個共享空間）

在 M1／M2-a 試用的環境（Windows、Docker Desktop、原本的 `notes_dev` 資料庫）上進行。需要四個彼此獨立的瀏覽器視窗（例如 Chrome、Chrome 無痕、Edge、Edge InPrivate），各登入一個帳號；以下稱 A（管理者）、B、C、D。每個帳號都要在驗證器 App 設定兩步驟驗證。

## 準備：升級到 M2-s

```powershell
cd app
git fetch
git checkout m2s          # 驗收通過後會併入 main
npm ci
npm run db:migrate        # 已有資料時先自動備份，畫面會顯示 backup …dump，再顯示 applied 0002_spaces.sql
npm run dev               # 網頁
npm run collab            # 協作伺服器（另開一個終端機）
```

升級前的資料備份在 `app/backups/`。需要退回 M1 時見 README「升級到 M2-s」。

## 步驟與預期結果

請在每一步的「結果」欄填「通過」或描述看到的情況。

| # | 操作 | 預期 | 結果 |
| --- | --- | --- | --- |
| 1 | A 登入 | 側邊欄最上方是「我的頁面」，裡面是 A 在 M1 建立的頁面；別人在 M1 建立的頁面不在這裡 | |
| 2 | A 在「設定 → 邀請成員」邀請到總共四個帳號，B、C、D 各自開連結設定密碼與兩步驟驗證 | 四個帳號都能登入；每個人一開始只看到自己的「我的頁面」 | |
| 3 | A 再建立第五個邀請 | 顯示「帳號已達上限（最多 4 個…）」，沒有產生連結 | |
| 4 | A 按「＋ 新增共享空間」建立「共享一」，在 ⚙ 空間設定中加入 B、C | B、C 的側邊欄在 2 秒內出現「共享一（3 人）」；D 沒有 | |
| 5 | B 建立「共享二」，加入 D 與 A | 現在有兩個共享空間；C 看不到「共享二」 | |
| 6 | 每個人在「我的頁面」各建一頁；A 把自己私人頁的網址貼到 B 的瀏覽器開啟 | B 看到無法開啟的提示，看不到內容與標題 | |
| 7 | A 把一個私人頁拖到「共享一」的標題上 | 先跳出確認：「移到「共享一」後，A、B、C 會看到」；確認後 B、C 2 秒內看到這一頁（含子頁面） | |
| 8 | B、C 同時編輯步驟 7 的頁面 | 兩人的修改都即時出現；狀態顯示「已儲存」 | |
| 9 | B 開著這一頁；A 把它拖回「我的頁面」 | 確認視窗列出「B、C 將看不到」；確認後 B 的畫面顯示「你已無法存取這個頁面」，側邊欄也不再有這一頁 | |
| 10 | C 開著「共享一」的某一頁；A 在空間設定中移除 C | C 的畫面顯示「你已無法存取這個頁面」；C 的側邊欄不再有「共享一」 | |
| 11 | D 在「共享二」的空間設定中按「退出空間」 | D 的側邊欄不再有「共享二」；B 的成員清單少了 D | |
| 12 | A 在「共享一」的頁面插入頁面連結（「/頁面連結」），指向 A 的私人頁；B 開啟該頁 | A 看到標題；B 只看到「無法開啟的頁面」，沒有標題；B 插入連結的清單裡沒有 A 的私人頁 | |
| 13 | B 在 ⚙ 中刪除「共享二」 | A 的側邊欄不再有「共享二」；B 的垃圾桶出現原本在「共享二」的頁面；B 還原後頁面出現在 B 的「我的頁面」，A 看不到 | |
| 14 | 四個瀏覽器都重新整理 | 每個人看到的空間與頁面和重新整理前相同 | |
