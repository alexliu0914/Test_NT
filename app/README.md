# 筆記平台（M1 基礎平台）

自架的協作筆記平台，最多四個帳號。M1 交付認證、頁面樹與垃圾桶，並把 M0 驗證過的協作核心移植成正式服務；M2-a 交付編輯器；M2-s 加入個人空間與共享空間。

## 架構

| 部分 | 位置 | 說明 |
| --- | --- | --- |
| 網頁與 API | `src/`（Next.js 16、App Router） | 登入、兩步驟驗證、邀請、設定、頁面樹、編輯器頁面；API 在 `src/app/api/` |
| 認證 | `src/lib/auth.ts` | Better Auth 1.7（帳號密碼＋TOTP 外掛）；公開註冊關閉 |
| 資料庫 | `src/lib/schema.ts`、`migrations/` | Drizzle ORM；認證資料表由 Better Auth 官方 CLI 產生；每個遷移都有 `migrations/down/` 回滾檔 |
| 協作伺服器 | `collab/server.mjs` | 由 M0 原型移植（提交後才確認與廣播、update_id 去重、還原、衝突副本、背壓）；改用 5 分鐘協作憑證與正式 session |
| 共用程式 | `shared/` | 協作用戶端、文件模型、BlockNote 結構、IndexedDB 草稿、協作憑證（Node 測試與瀏覽器共用） |
| 授權（M2-s） | `src/lib/access.ts`、`src/lib/spaces.ts` | 使用者是頁面所屬空間的成員才能讀寫；無權限一律 404。協作伺服器在連線與每批提交時重新授權（`collab/server.mjs`） |
| 測試 | `test/` | 執行器與 M0 相同規則；案例清單見下 |

## 本機開發

```bash
cd app
cp .env.example .env          # 填入 BETTER_AUTH_SECRET、COLLAB_SECRET（各執行一次下一行，產生兩組不同的值）
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
docker compose -f docker-compose.test.yml up -d --wait
docker compose -f docker-compose.test.yml exec postgres createdb -U postgres notes_dev
npm ci
npm run db:migrate
npm run admin:create -- --email you@example.com --name 你的名字     # 建立第一個管理者與工作區
npm run dev                    # 網頁 http://localhost:3000
npm run collab                 # 協作伺服器 ws://localhost:3001（另開一個終端機）
```

第一次登入必須設定兩步驟驗證；之後的帳號由管理者在「設定 → 邀請成員」建立邀請連結（72 小時、只能用一次）。最多四個帳號（含管理者），已滿時無法建立或兌換邀請。

### 空間（M2-s）

- 每個帳號有一個個人空間（側邊欄的「我的頁面」），只有本人看得到；管理者也看不到別人的個人空間。
- 「＋ 新增共享空間」建立共享空間；建立者在空間設定（⚙）中加入或移除成員、改名、刪除空間。成員都可以編輯，可以自己退出。
- 把頁面拖到另一個空間（或空間標題）時，會先列出「誰會看到、誰將看不到」，確認後整棵子樹一起移動。
- 被移出空間（或頁面被移到看不到的空間）時，正在開啟的頁面顯示「你已無法存取這個頁面」；尚未同步的內容只保留在這台裝置上、可下載，不會再送出。之後重新取得權限時也不會自動補送，由使用者選擇下載、另存為衝突副本或捨棄。
- 刪除共享空間：空間內的頁面移到建立者「我的頁面」的垃圾桶（30 天內可還原，還原後只有建立者看得到）。
- 已知限制：撤銷只能停止伺服器端的存取；已經下載的檔案、瀏覽器快取或截圖不在系統控制範圍。

### 協作游標與儲存狀態（M2-b）

- 同一頁的其他人：編輯區上方列出在線的人（名字與顏色），文件中顯示他們的游標。名字與顏色由伺服器依登入帳號決定，用戶端不能自己指定；同一頁的人優先分配不同顏色（8 色），離開後釋放。
- 游標只在同一頁、已登入並有權限的連線之間轉送，不寫入資料庫，也不影響「已儲存」。連線關閉、登入被撤銷、失去權限時，其他人立即看不到該游標；網路異常中斷時最多 30 秒（心跳逾時）後清除。
- 五種儲存狀態（判定規則見 `shared/save-state.js`）：

| 狀態 | 意思 |
| --- | --- |
| 已儲存 | 所有修改都已收到伺服器「已提交」的確認 |
| 儲存中 | 已存在這台裝置，正在等伺服器提交 |
| 離線，內容保存在此裝置 | 沒有連上伺服器；修改已存在這台裝置，重新連線後自動送出 |
| 儲存失敗 | 已連線，但伺服器回報資料庫無法寫入（或超過 10 秒仍未確認）；修改仍保存在這台裝置，恢復後自動送出 |
| 尚未存到此裝置 | 剛輸入、還沒寫入這台裝置（此時關閉可能遺失） |

- 貼到空白行時，貼上的內容放進自己新建的區塊，再移除原本的空白行（看起來與一般貼上相同，復原一次就回到空白行）。兩人同時貼到同一個空白行時，各自的標題、清單與段落都保持完整；自己所在的空白行被別人的貼上換掉時，會在原位置補一個空白行（F-M2-08）。
- 一人改區塊類型（標題、清單……）時，另一人同時在該區塊打的字由協作伺服器補進新的區塊類型，不會遺失；改類型的人關閉頁面、離線或伺服器重新啟動也一樣（F-M2-09）。
- 復原（Ctrl+Z）／重做（Ctrl+Shift+Z）「只改了區塊類型」的那一步時，只改回類型，保留別人之後在該區塊打的字；其他復原與重做照原本（F-M2-10）。
- 有尚未同步的修改時：關閉分頁會出現瀏覽器的離開提醒；在側邊欄切換頁面會先等 1.5 秒讓它同步，仍未同步就詢問是否離開（內容保存在此裝置，下次開啟該頁時補送）。側邊欄在這台裝置上有尚未同步修改的頁面旁標示「未同步」（只看目前帳號自己的草稿）。

### 升級到 M2-s（遷移 0002）

`npm run db:migrate` 在已有資料的資料庫套用 0002 前，會先以 `pg_dump` 自動備份到 `backups/`，並還原到暫存資料庫比對各表筆數與結構，驗證失敗就不遷移。既有頁面依建立者歸到各自的個人空間（不自動公開）；之後請建立共享空間並把要共用的頁面拖進去。
回滾：還沒有新資料時 `node scripts/migrate.mjs down` 可直接回滾；已有共享空間、成員、跨空間搬移或新建頁面時會拒絕，請改用 `node scripts/migrate.mjs restore backups/<檔名>.dump` 從遷移前的備份還原。

Windows（PowerShell）也適用以上指令；需先啟動 Docker Desktop。

## 測試

```bash
cd app
export PGHOST=127.0.0.1 PGPORT=54329 PGUSER=postgres
bash test/setup-test-db.sh                         # 建立 notes_test（只會對 *_test 資料庫執行）
COLLAB_PUBLIC_URL=ws://127.0.0.1:27601 npx next build
npx playwright install --with-deps chromium
node test/runner-selftest.mjs                      # 執行器自我測試（21 項）
node test/run.js MIG-01=3 AUTH-01=10 SEC-02=20 PAGE-05=60 M0-01=100 BR-01=20 BR-04=20 ...
python3 test/mutations.py --stage m2-b              # 該階段的植入缺陷都必須被抓到（M1 26 個＋M2-a 3 個＋M2-s 9 個＋M2-b 8 個）
```

### 分段執行（M2 起）

`test/manifest.json` 列出每個案例與變異所屬的階段（m1、m2-a、m2-s、m2-b～m2-d）、群組（api、core、browser、perf）與輪數；`test/m1-baseline.json` 是 M1 封存基線（5f7bd04），`test/accepted-baselines.json` 是已驗收的 M2 階段（M2-a `2141293`、M2-s `d78a094`）；這些案例與變異不能移除、改階段或減少完整輪數，否則執行器拒絕執行。

```bash
node test/run.js --stage m2-a --group browser --full    # 該階段（含之前）的全部案例；之後階段的記為 NOT_APPLICABLE_NOT_IMPLEMENTED
python3 test/mutations.py --stage m2-a                  # 該階段（含之前）的全部變異
python3 test/mutations.py --check                       # 只檢查 manifest 與變異定義（編號重複、未登記、已驗收階段被移除）
node test/unit/conversion-rescue.mjs                    # 改類型補救（F-M2-09）的單元測試，不需要資料庫
```

CI（`.github/workflows/app.yml`）推送時用 manifest 的 `current` 階段跑縮減輪數；手動觸發可指定階段並跑完整輪數與變異。

| 編號 | 內容 |
| --- | --- |
| MIG-01 | 每個遷移回滾後重新套用，結構完全相同；全部回滾後沒有殘留 |
| AUTH-01～07 | 登入、相同的錯誤訊息、不能未經邀請註冊、邀請一次有效與過期、TOTP 與備援碼、未設定兩步驟驗證不能使用、密碼規則 |
| SEC-01／02／03／05／06 | 登入失敗鎖定、撤銷其他裝置（含協作連線 2 秒內中斷）、跨站請求、未登入的每個 API、協作憑證竄改／過期／錯頁／撤銷 |
| PAGE-01～05 | 對方 2 秒內看到變更、不能移到自己的子頁面、整批刪除與還原、30 天永久刪除、兩人隨機操作的不變量 |
| M0-01～11、M0-17 | M0 協作核心測試，改在正式協作伺服器與正式 session 上執行 |
| BR-01～04 | 真正的 Chromium：兩人編輯與還原、IndexedDB（含正式登入撤銷、不同帳號）、正式介面流程（邀請→兩步驟驗證→頁面樹）、兩人同時開始編輯新頁面 |
| EDIT-01、EDIT-02（M2-a） | 每種區塊建立、編輯、刪除、重新整理後一致；頁面連結不顯示已刪除頁面的標題；斜線指令（繁中）、Markdown 快捷輸入、拖曳 |
| BR-05（M2-a） | 兩人同一位置同時建立表格、巢狀清單、貼上多區塊（含同步前、離線、同時改同一區塊的類型，F-M2-01） |
| SEC-04（M2-a） | 貼上、同步、重新整理時不執行任何程式、不留下危險連結（script、事件屬性、javascript:／data:／vbscript:、SVG、MathML） |
| ACL-01（M2-s） | 四人各自的個人空間：其他人從頁面樹、垃圾桶、改名、移動、刪除、還原、協作憑證、別人的憑證、即時推送都存取不到；所有 API 路由都必須列入註冊表 |
| ACL-02（M2-s） | 成員管理（只有建立者）、移除與退出（2 秒內消失、協作連線中斷）、在途修改不提交、刪除空間（含注入失敗）、權限恢復後舊草稿不自動補送 |
| ACL-03（M2-s） | 四人隨機並行建頁、移動（含跨空間）、刪除、還原、成員變動、刪除空間：存取、同空間、個人空間只有本人等不變量 |
| ACL-04（M2-s） | 真正的 Chromium、四個帳號：建立共享空間、邀請、跨空間拖曳的確認、被移除時的提示、連結不洩漏看不到的頁面 |
| MIG-02（M2-s） | 以 M1 資料遷移 0002：每頁歸建立者的個人空間；安全時可回滾；四類不安全資料讓回滾拒絕；可從遷移前備份完整還原 |
| AUTH-08（M2-s） | 最多四個帳號：第五個被拒（邀請、兌換、管理者指令、直接寫入資料庫）；剩一個名額時同時兌換只成功一個；停用的帳號仍占名額 |
| COL-01（M2-b） | 兩人在同一段落同時輸入：沒有字元遺失或重複、兩端與資料庫一致、對方 1 秒內看到；兩人先後貼到同一個空白行（等對方的內容收到後才貼上）：各自結構完整、沒有合併；單人貼上後復原、重做；一人改區塊類型時另一人同時打字（含斷線、關閉頁面、伺服器重新啟動、取代反例）、復原與重做改類型：每個字恰好一次 |
| COL-02（M2-b） | 一方刪除區塊時另一方正在該區塊輸入：不崩潰、最終一致、其他段落與後續編輯不受影響 |
| COL-03（M2-b） | 一方離線 30 秒持續編輯後重新連線：每個待確認的 update_id 都被提交 |
| COL-04（M2-b） | 四個帳號的游標：伺服器確認的名字與顏色、冒名無效、不跨頁、同帳號兩條連線、色票分配與回收、異常斷線清除、游標不寫入資料庫 |
| COL-06（M2-b） | 編輯中 kill -9 協作服務並重啟：沒有遺失、沒有重複套用 |
| COL-07（M2-b） | 一顯示「已儲存」就 kill -9：資料庫已有那些修改；不對應的確認不會讓狀態變成已儲存 |
| COL-09（M2-b） | 協作中撤銷登入：2 秒內中斷、游標消失、之後的輸入不送出（重新整理後也不補送）、同帳號另一台裝置的游標保留 |
| COL-10（M2-b） | 離線修改後關閉瀏覽器、恢復網路重新開啟：草稿存活並補送；收到確認前不顯示已儲存 |
| COL-11（M2-b） | 資料庫無法寫入時繼續編輯：顯示「儲存失敗」、背壓與本機暫存生效；恢復後沒有遺失或重複；狀態判定表的交疊情境 |

瀏覽器測試的網頁固定在 27600、協作伺服器在 27601；網頁的 CSP 在建置時寫入協作網址，所以建置時要設定 `COLLAB_PUBLIC_URL=ws://127.0.0.1:27601`。
